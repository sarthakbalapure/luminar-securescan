## 6. Sample Findings

Section headline:

Findings that are clear, prioritized, and actionable.

Sample finding 1:

Title: Content Security Policy header is missing

Severity: Medium

Category: Security Headers

Business impact: Browser-side attacks may have greater impact if an injection issue exists.

Recommended fix: Deploy a reviewed Content Security Policy and roll it out in report-only mode before enforcement.

Sample finding 2:

Title: Cookie is missing Secure flag

Severity: High

Category: Cookie Security

Business impact: Session data may be exposed over insecure connections.

Recommended fix: Set the Secure flag for session cookies and confirm all authentication flows use HTTPS.

Sample finding 3:

Title: TLS certificate is expired

Severity: High

Category: Transport Security

Business impact: Users may see browser warnings, lose trust, or be unable to access the application safely.

Recommended fix: Renew the certificate and enable automated certificate monitoring.

Sample finding 4:

Title: Exposed environment file detected

Severity: Critical

Category: Sensitive File Exposure

Business impact: Configuration values or secrets may be publicly accessible.

Recommended fix: Remove the file from the public web root, block access at the server level, and rotate any exposed credentials.

## 12. FAQ

Question: Is LuminarIQ SecureScan a penetration testing tool?

Answer:

SecureScan is a defensive baseline security audit platform. It helps identify common risks and configuration issues, but it is not a replacement for a full manual penetration test.

Question: Can I scan any website?

Answer:

No. You should only scan websites, applications, APIs, or repositories that you own or have explicit authorization to test.

Question: Does SecureScan run destructive attacks?

Answer:

No. The MVP is designed around safe, defensive, non-invasive baseline checks.

Question: What does the security score mean?

Answer:

The score summarizes detected findings from 0 to 100. Critical and High findings reduce the score more than Low or Info findings.

Question: Does it support APIs?

Answer:

Yes. SecureScan can use OpenAPI or Swagger specifications to run defensive API baseline checks.

Question: Does it support source code repositories?

Answer:

Yes. Repository scans can check for secret indicators, dependency vulnerabilities, static code issues, Dockerfile risks, and insecure configuration patterns.

Question: Are findings mapped to OWASP?

Answer:

Yes. Findings are mapped to common OWASP categories where applicable, helping teams communicate risk clearly.

Question: Can I generate reports for clients?

Answer:

Yes. SecureScan supports executive, technical, and full PDF reports. Agency plans can include white-label reporting options.

Question: Will developers understand what to fix?

Answer:

Yes. Findings include evidence, technical impact, remediation guidance, code or configuration examples, and retest steps.

Question: Does SecureScan store secrets?

Answer:

SecureScan is designed to redact sensitive evidence and avoid storing plaintext transient tokens. Reports and UI should never display full secret values.

Question: Can I retest after fixing issues?

Answer:

Yes. The retest workflow helps teams confirm whether previously detected findings have been fixed.
